FOR OUR DDD
How I Integrated DDD into the Existing System

I integrated DDD into the payroll module without rewriting the entire HRIS.

    The existing HR payroll page collects the employee salary and attendance data, then creates a payroll command:

        hr/payroll.php
                ↓
        GeneratePayslipCommand
                ↓
        GeneratePayslipHandler
                ↓
        Payslip Domain Model
                ↓
        PdoPayslipRepository
                ↓
        MySQL payslips table

Main DDD parts
    Presentation Layer: hr/payroll.php

    Collects payroll data and displays results.
    Application Layer:

    GeneratePayslipCommand.php and GeneratePayslipHandler.php

    Coordinates the generate-payslip use case.
    Domain Layer: Payslip.php, Money.php, and LateDeductionPolicy.php

    Contains the actual payroll rules and calculations.
    Infrastructure Layer: PdoPayslipRepository.php

    Saves the calculated payslip to MySQL.

The important principle is:

    The page collects data.
    The domain calculates payroll.
    The repository saves the result.
    This keeps the payroll rules separate from the HTML and database code.


How TDD Works in My System

    TDD means Test-Driven Development. I write automated tests for the payroll behavior and run them using PHPUnit.

The process is:

    Write a test
        ↓
    Run the test
        ↓
    Fix or implement the code
        ↓
    Run the test again

The tests verify:
    Salary calculation
    Allowance
    Overtime
    Late deductions
    Net pay
    Payslip status changes
    Repository saving

For example, one test checks that:

    Late deductions reduce net pay,
    but do not reduce gross pay.


How to Run the TDD Tests

    From the project root, run:

        powershell
        vendor/bin/phpunit tests/Unit/Domain/Payroll

    To run all project tests:
        powershell
        vendor/bin/phpunit


    The successful result is:
    text
        OK (64 tests, 90 assertions)

    This means:

    64 automated tests passed
    90 conditions were verified
    0 failures
    0 errors


TDD is not a separate page in the system. It is the automated testing process used to prove that the DDD payroll rules work correctly.
